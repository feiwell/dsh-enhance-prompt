# dsh-enhance-prompt

给 DeepSeek Harness 用的一个小插件，用来增强提示词。

平时在输入栏里随手敲的提示词，往往缺上下文、缺约束，直接发给模型，得到的答案经常跑偏。这个插件做的事很简单：在输入栏右侧加了一个按钮，点一下就把你输入的提示词改写成一版更清晰、更具体的版本，改完直接替换输入框里的文字。不满意的话，再点一下就能回到原文。

除了默认的「日常办公」，还提供「代码开发」和「设计创意」两种模式，让改写结果更贴合你要做的事——写文档、写代码还是做设计，收束的方向是不一样的。

## 安装

一条命令搞定：

```sh
dsh plugin --profile web add feiwell/dsh-enhance-prompt
```

装完重启 DeepSeek Harness 就能看到按钮。插件自带 `cordis.patch.yml`，安装时会把插件自动写进 web profile，不用手动改配置。环境要求 Node ≥ 22.19.0，DeepSeek Harness 自带的 Node 已经满足。

## 怎么用

输入栏右侧会出现两个控件：一个模式菜单，一个增强按钮。

模式菜单默认选「日常办公」，点开可以在「代码开发」和「设计创意」之间切换，菜单是向上弹出的。

输入框里有提示词的时候就可以点增强按钮。点下去之后按钮显示「增强中…」，改写完成后结果直接替换输入框里的文字，按钮变成「恢复原文」——觉得改得不好就点一下还原，原文一直留着。

几个细节：

- 输入框为空时按钮是灰的，提示「先输入内容，再增强提示词」。
- 一次改写最多等 30 秒，超时会提示「增强超时」，你的提示词原样不动。
- 模型出错、请求失败也一样，提示词不会被半截结果覆盖。
- 正在发送消息、或者模型正在输出判定的时候，按钮会暂时禁用，避免跟会话状态打架。

## 三种模式的区别

模式不影响底层模型和改写模板，只影响改写时怎么"收"你的提示词：

**日常办公（work）** 把提示词当成办公任务来改：帮你补上受众是谁、语气怎么样、篇幅多长、最终要交付什么。如果涉及 Word、PPT、Excel，会写清楚是新建文件还是修改已有文件。

**代码开发（code）** 把提示词当成一个要实现的功能来改：写明白要做什么、输入输出是什么、边界在哪、错误怎么处理、做到什么程度算完成。它不会替你选技术栈，也不会把实现代码直接写进提示词里。

**设计创意（design）** 把提示词当成设计任务来改：交代清楚媒介、风格、受众、尺寸或比例、哪些元素必须保留、哪些明确不要。描述用的是设计语言，不会往代码开发或者数据库的方向扩。

## /enhance 命令

插件同时注册了一个 `/enhance` 命令，比如：

```
/enhance 帮我写个登录页
```

不过命令返回的是命令结果，不会动输入框里的文字。想在输入栏里原地改写，用按钮就行。

## 接口

按钮背后调用的是插件自己的 `POST /api/enhance-prompt`：

```json
{ "input": "要增强的提示词", "mode": "work | code | design" }
```

`mode` 只认 `work`、`code`、`design` 三个值，传别的都按 `work` 处理。成功时返回 `{ "text": ... }`，出问题时返回对应的 `error` 和 4xx/5xx 状态码。

## 实现上的一些事

改写请求走的是你当前会话里选的默认模型，参数是 temperature 0.2、maxTokens 800。推理档位不跟输入栏里的选择走：改写是一段短文本，会自动用这个模型提供的最低档，避免高推理档把时间耗在看不见的思考上。系统提示词和用户提示词是内置的改写模板，会再按所选模式在末尾追加一段收束说明。

有两点是刻意保证的：改写结果严格跟随你的输入语言——中文进中文出，中英混排就保持混排，不会自作主张翻译成单语；另外插件只增强你的提示词，不会替你回答里面的问题，也不会把整份主对话模板塞进请求。

按钮注册在 `conversation.input.right` 插槽上，由插件自己的前端入口渲染，没有改动 `@deepseek-ai/dsh-client-ui-conversation` 里的任何东西。

## 项目结构

```
index.js         服务端入口：注册 /enhance 命令和 /api/enhance-prompt 接口
lib/client.js    前端入口：在输入栏右侧渲染模式菜单和增强按钮
cordis.patch.yml 安装补丁：把插件自动加进 web profile
```
